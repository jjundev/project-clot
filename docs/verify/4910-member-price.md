# 4910 내 가격(쿠폰 적용가) 조사 — 2026-10-10 ~ 10-11

결론: **가격은 비로그인 HTTPS로 대량 수집하고, 로그인은 "내 쿠폰함 + 판매처별 쿠폰 적용 여부" 확인에만 쓴다.**
4910 화면 가격 = `ceil10(목록가 − 쓸 수 있는 쿠폰 중 최대 할인)` (예상 구매가는 여기서 포인트를 더 뺌).

## 1. 지금 찜 기능이 기록하는 `member_price`는 4910 가격이 아니다

`src/site4910/liked.js`는 `/api/v2/goods/{sno}/`를 회원 토큰으로 호출해 `goods.price`를 회원가로 기록한다.
이 응답은 **에이블리 앱 기준**이다(`X-App-Type` 헤더 없음).

| 해링턴 재킷 57821918 (목록가 85,400) | 가격 | 구성 |
|---|---:|---|
| `/api/v2/goods` 회원 | 75,900 | 에이블리 브랜드 10% + 숨은 할인 = `(L−2000)×0.91` |
| `/api/v2/goods` 비로그인 | 70,890 | 에이블리 첫구매 15% + 2,000 = `(L−2000)×0.85` |
| **4910 웹 (실제)** | **68,320** | [4910] 첫구매 20% (−17,080). 예상 구매가 65,320 = 포인트 −3,000 |

- 에이블리 기준 가격은 아래 공식으로 341/341개가 정확히 맞았다. 다만 4910과 무관하므로 참고용이다.
  `ceil10(min(L, 플랫폼 쿠폰 적용가, L≥~2만: L×0.91, L≥4만: (L−2000)×0.91))`
- 목록 API에 회원 토큰을 붙여도 `SALES_PRICE`는 그대로다. 목록만으로는 회원가가 나오지 않는다.

## 2. 4910 웹이 가격을 얻는 방식

4910 웹(`static.4910.kr` 번들)은 모든 요청에 아래 헤더를 붙인다.

```
X-App-Type: AGLO
X-App-Version: 0.1.0
X-Device-Type: PCWeb        # 모바일웹은 MobileWeb
Authorization: JWT <ably-jwt-token 쿠키>   # 비로그인이면 X-Anonymous-Token
```

상품 페이지가 가격 계산에 쓰는 호출(내장 브라우저에서 XHR을 가로채 확인):

| API | 내용 | 스크립트 호출 |
|---|---|---|
| `GET /aglo/api/goods/{sno}/?channel=0&member_gender=MALE` | 상세 (price = 목록가) | ❌ Cloudflare 403 |
| `GET /aglo/api/goods/{sno}/coupons/?channel=0` | 이 상품에 쓸 수 있는 쿠폰 | ❌ 403 |
| `GET /aglo/api/goods/{sno}/discounts/?channel=0` | `max_discount_coupon`, `max_emoney_discount` → "나의 예상 구매가" | ❌ 403 |
| `GET /aglo/api/members/me/coupons/` | **내 쿠폰함** (할인율, 최대 할인, 기간, 사용 가능 여부) | ✅ |
| `GET /aglo/api/members/me/` | `emoney`(포인트 잔액) | ✅ |
| `GET /aglo/api/coupons/best-coupon?options=[{"sno":<옵션sno>,"ea":1}]` | 그 옵션에 적용되는 최적 쿠폰 + `coupon_discount` | ✅ |
| `GET /aglo/api/coupons/{couponSno}/goods?limit=&category=` | 쿠폰 적용 상품 목록 (브랜드 필터 없음, 86만~116만 건) | ✅ (너무 큼) |

- `/aglo/api/goods/*`는 Cloudflare가 브라우저가 아닌 요청을 막는다(헤더를 맞춰도 403). **우회하지 않는다.**
- `/aglo/api/coupons/{sno}`에는 적용 대상 조건식(`goods_segment_expression`)이 없다.
- 옵션 sno는 비로그인 `/api/v2/goods/{sno}/`의 `goods.linked_option.sno`에서 얻는다.

## 3. 4910 가격 계산식과 검증

```
쿠폰가 = ceil10(L − max(min(쿠폰.max, floor(L × 쿠폰.% / 100))  for 쿠폰 in 그 판매처에 적용되는 내 쿠폰))
       (L ≥ 쿠폰 최소금액 10,000원일 때만)
예상 구매가 = 쿠폰가 − min(포인트 잔액, max_emoney_discount)
```

10/11 기준 내 쿠폰함(사용 가능, 모두 2026-10-31 종료):

| 쿠폰 | 할인 | 최대 할인 |
|---|---:|---:|
| [4910] 첫구매 20% | 20% | 30,000 |
| 해외 브랜드 18% | 18% | 100,000 |
| [프리미엄] 해외 브랜드 15% | 15% | 130,000 |

`best-coupon`으로 49개(찜 9개와 무작위 40개)를 검증했다.

- **쿠폰이 적용되는 판매처에서는 27/27개가 정확히 일치했다.** 고가 상품은 최대 할인 한도 때문에 18%로 넘어간다. 예: 212,300 → 174,090.
- **적용 여부는 판매처 단위로 전부 아니면 전무다.**
  - 적용: LUXURYJP, 모에모에, 사쿠라니폰, 잇츠와이, 일본쵸루상, 오오키니, 블리블리샵 등
  - 미적용(목록가 그대로): 바잉누나, 룩스굿, 모드픽, 제타스타, 아마존임, 심플조이, 아키바플레이스, 여기서부터일본
  - 판매처 전용 쿠폰: TNGT ([4910] TNGT 5%)
- 그래서 판매처마다 1~2개 상품으로 `best-coupon`을 확인하면 나머지는 로컬에서 계산할 수 있다. 4910 전체는 15,893개, 판매처는 55곳이다.
- **보충(2026-10-11 첫 실행):** 판매처 전용 쿠폰은 쿠폰함 쿠폰과 함께 적용될 수 있다. 전용 쿠폰에 최소금액(예: `[4910] 인기 스포츠 20%`, 50,000원 이상)이 있으면 고가 상품은 전용 쿠폰, 저가 상품은 쿠폰함 쿠폰이 best가 된다. 그래서 판매처의 쿠폰 집합은 표본들의 best를 합친 것이다. 또 `best-coupon`의 할인은 상세 가격(`first_page_rendering.price`) 기준이라 목록 `sale_price`와 다를 수 있다(예: 목록 81,200, 할인 14,640 = 73,200의 20%).

## 5. 주의

- 쿠폰가는 **개인 가격이고 계속 바뀐다.** 첫구매 쿠폰은 4910 첫 구매 뒤 사라지고, 쿠폰들은 10/31에 끝난다. 쿠폰이 바뀌는 날 가격이 한꺼번에 "오른다". 그래서 가격 하락 판단은 목록가 기준으로 하고, 쿠폰가는 함께 표시하는 정도가 안전하다.
- 쿠폰함이 바뀌면 판매처별 적용 여부도 다시 확인해야 한다(매일 다시 확인).
- `discounts` 응답에 `has_purchased_at_4910: true`가 있는데도 첫구매 쿠폰은 쓸 수 있는 상태였다.
- 조사 스크립트는 세션 scratchpad에만 있고 커밋하지 않았다. 모든 호출은 읽기 전용이었다.
