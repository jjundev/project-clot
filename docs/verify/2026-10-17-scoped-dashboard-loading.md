# 범위별 검색 로딩 검증 — 2026-10-17

구현 기준은 `docs/superpowers/specs/2026-10-17-scoped-dashboard-loading.md`다. 공개 사이트에 배포한 결과가 아니라 격리 브랜치의 로컬 산출물과 합성 입력 검증이다. 기존 `data/4910-all.js`, 수집 DB와 가격 정책은 변경하지 않았다.

## 동작과 회귀 검증

- 전체·무신사·4910 기본 첫 페이지를 HTML에 포함한다. 인덱스를 차단해도 저장된 비기본 조건에서 상품이 보인다. 기본 조건과 다른 미리보기 및 이전 결과는 준비 중임을 표시하고 결과 건수를 확정하지 않는다.
- 인덱스는 출처×카테고리로 나누고 선택 범위만 요청한다. 다른 범위의 미확인 건수는 `—`, 확인한 빈 범위는 `0`이다. 교차 집계를 위해 추가 다운로드하지 않는다.
- 다운로드 캐시와 진행 중 요청을 재사용하고, 검색·경로·카드 다운로드의 공유 실행 슬롯은 4개다. 새 검색은 오래된 대기를 제거하고 이전 호출을 `STALE_RESULT`로 끝낸다. 이미 실행 중인 정상 다운로드는 캐시에 남는다.
- 직접 링크는 미리보기 또는 FNV-1a 버킷별 상품→카드 경로로 해결한다. 선택 검색 범위를 유지한다. 이전의 필터 초기화는 전체 인덱스를 유발하므로 V2에서는 적용하지 않는다.
- HTTP Worker와 file 대체 경로, 브랜드 다중 선택·키보드 포커스, 상세 이전/다음, 최근 90일/전체 이력과 재시도, 360개 카드 창을 검사한다.
- 440,129개 규모에서는 마지막 상품 검색, 페이지 왕복과 오래된 상세 응답 무시를 검사한다. 전체·출처 건수와 첫 페이지 120개 제한을 유지한다. 규모 fixture는 양쪽 출처와 top/outer/etc 범위를 포함한다.
- 원문 자산 최대 256KiB, route 버킷 분할, 빈 데이터, 잘못된 버전/범위/경로 대상, 가격 미관측 상품을 검증한다. 검증기는 JSON 객체 키 삽입 순서에 의존하지 않고 배열 순서는 검증한다.

## 같은 데이터로 한 성능 비교

기준 코드 `ecb32eb`와 변경 코드에 같은 합성 fixture 30,628개를 입력했다. 파일 참조를 제외하고 키순 정렬한 인덱스 행의 SHA-256은 양쪽 모두 `275415364fc7650a1b7b1abecab25d8d3e32ca6356dc4a3e5faf7354e359df67`이다. 두 산출물 모두 `verify-dashboard-build.js`를 통과했다.

조건: macOS, 설치된 Chrome 155, headless 1440×1000, localhost HTTP gzip, CPU/네트워크 제한 없음, 각 시나리오마다 새로운 브라우저 컨텍스트 3회. 외부 HTTPS 자산을 양쪽 모두 차단했다. 첫 카드는 10ms 관찰 간격으로 측정한다. 검색 준비 시간에는 debounce를 거치는 실제 무결과 질의와 Worker의 응답이 포함되므로 단순 인덱스 다운로드 시간과 다르다. 전송량은 Worker 요청을 포함한 BrowserContext 응답의 `responseBodySize` 합계다. HTML·카드·헤더는 아래 인덱스 바이트 합계에 포함하지 않는다. heap 값은 메인 스레드만 관측하며 Worker 메모리를 포함하지 않는다.

표의 시간은 3회 중앙값이다.

| 시나리오 | 버전 | 첫 카드 | 검색 준비 | 인덱스 파일 | 압축 인덱스 전송량 |
|---|---|---:|---:|---:|---:|
| 무신사·상의 | 기준 | 155.8 ms | 391.7 ms | 26 | 266,947 B |
| 무신사·상의 | 변경 | 84.1 ms | 328.5 ms | 1 | 2,350 B |
| 전체 | 기준 | 77.2 ms | 310.8 ms | 26 | 266,947 B |
| 전체 | 변경 | 85.4 ms | 345.0 ms | 32 | 297,414 B |

무신사·상의의 인덱스 전송량은 약 99.1% 감소했다. 전체 검색은 모든 범위가 필요하며 이번 fixture에서는 분할에 따른 파일 수·압축 중복 때문에 전송량과 준비 시간이 늘었다. 양쪽 12개 샘플의 페이지 오류는 0건이다. 이 수치는 합성 데이터와 localhost 조건의 결과이며 공개 사이트의 실제 로딩 시간이나 실상품 건수를 증명하지 않는다.

측정 재현: 같은 fixture로 만든 두 산출물을 gzip HTTP 서버에서 제공하고 `measureDashboard(url, {runs:3, isolateExternal:true, scenarios:[{name:'musinsa-top',state:{src:'musinsa',cat:'top'}},{name:'all',state:{src:'all',cat:'all'}}]})`를 각각 실행한다. CLI의 URL/JSON 출력 인자도 유지했다.
