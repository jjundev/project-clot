# 추적 상태·가격 신선도 수정 검증

## 적용 정책

- 실제 관측과 가격 계산을 분리한다. 가격 불변이어도 실제 재관측 시각은 기록하고, 가격 누락·쿠폰 재계산은 기존 가격의 관측 시각을 갱신하지 않는다.
- 가격 신선도, 최근 하락 관측 시점, 하락 비교 간격은 각각 최대 48시간이다.
- 보류·추적 종료·근거 불충분·갱신 지연 상품은 기본 목록과 최저가·하락 집계에서 제외한다. 과거 기록 선택 및 상품번호 조회로 접근할 수 있다.
- 찜·수동 추적을 우선하며 옛 자동 발굴 데이터가 전체 수집의 범위 이탈을 우회하지 못하게 한다. 4910 찜 해제 이력도 현재 활성 스캔 상품을 가리지 않는다.
- 첫 관측이나 가격 기준 전환 직후에는 최저가로 표시하지 않는다. 보류 후 복귀 시 비교 근거를 재시작하며, 당일 재실행은 이전 날짜의 최종 관측과 비교한다.
- 인덱스·카드·Worker·file 폴백·상세의 공통 판정을 사용한다. 열린 화면은 1분 주기 및 탭 복귀 때 재집계한다.

기존 change-only 가격 이력을 관측 이력으로 역산하지 않는다. 과거 전체 수집 DB에 새 관측 정보가 없으면 과거 기록으로 분류하고 다음 실제 수집부터 근거를 쌓는다. 기존 일별 실제 가격 로그는 그 가격의 관측 근거로 사용한다. 당일 재시도의 회원가·판매가·추정가 시각도 각각 기록한다.

## 실제 스냅샷 회귀

입력은 읽기 전용 사본이다. watched DB는 원격 main의 10월 25일 데이터, 무신사 Release의 마지막 실제 수집일은 10월 24일, 4910 Release의 실제 수집일은 10월 25일이다. 생성 결과와 검증 로그는 `/tmp/clot-tracking-audit.9Jk4Wx/`에 보관했다.

| 항목 | 결과 |
|---|---:|
| 전체 산출물 상품 | 505,570 |
| 4910 상품 | 189,425 |
| 기존 DB에서 최근 관측이 입증되는 기본 조회 상품 | 137 |
| 문제였던 옛 자동 발굴 상품 | 43 |
| 위 상품 중 과거 기록으로 보존 | 43 |
| 위 상품 중 기본 목록 / 최저가 / 하락 | 0 / 0 / 0 |
| 무신사 보류 상품 | 1,672 |

카드 asset 전체를 순회해 43개 ID를 독립 SQL 대상 집합과 대조했다. 첫 120개 미리보기만 확인한 결과가 아니다. `5115812`도 `STOPPED`, 최저가 false, 하락 0으로 확인했다. 과거 기록의 가격은 관리 주체의 최신 보존 이력을 따르므로 옛 자동 발굴 가격과 다를 수 있다.

생성과 전체 검증을 같은 Node 프로세스에서 연속 실행한 첫 시도는 기본 힙 한도에서 OOM이었다. 실제 Pages와 동일하게 별도 프로세스로 전체 검증을 실행하면 `--max-old-space-size=4096`에서 종료 코드 0으로 완료됐다. 검증 stdout:

```json
{"totalItems":505570,"total4910":189425,"scanState":"complete"}
```

해당 검증의 실행 시간은 42.06초, macOS 최대 RSS는 4,369,383,424 bytes였다. RSS와 V8 힙 상한은 서로 다른 지표다. 힙을 늘리거나 상품·이력을 제외하지 않았다. 생성/검증 프로세스를 분리한 기존 배포 경계를 유지한다.
