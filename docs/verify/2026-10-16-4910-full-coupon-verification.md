# 4910 전체 상품 쿠폰 가격 검증

전체 상품의 검증 처리, Release DB 갱신, 최종 공개 배포를 완료했다.

## 구현 및 검증

- 판매처별 최대 2개 표본을 다른 상품으로 일반화하지 않고, 전체 활성 상품과 찜 상품의 옵션을 검증 대상으로 삼는다.
- 쿠폰 목록에서 포함이 확인된 상품은 우선 확인한다. 불완전한 목록의 누락은 적용 불가 근거로 쓰지 않으며, 불완전한 경쟁 쿠폰 정보만으로 최적가를 확정하지 않는다.
- AGLO 기준 상세 가격, 동일 옵션, 수량 1의 best-coupon 적용 여부와 서버 할인액을 검증한다. 후보 쿠폰을 자동 발급하거나 포인트를 차감하지 않는다.
- 원본 DB 스냅샷, 날짜, 쿠폰 조건 지문 및 상품·옵션 식별자를 검증한 결과만 병합한다.
- 기존 raw 가격 이력은 보존하고 검증 메타데이터로 가격을 정정한다. 원본이 없던 오늘의 관측점만 추가한다.
- 동시 실행은 8개 파티션, 파티션별 클라이언트는 2개다. 처음 4개 클라이언트에서 HTTP 429가 확인되어 줄였다.
- 같은 날 목록 재수집이 검증 메타데이터를 초기화한 문제는, 최근 성공한 main 워크플로의 artifact에서 날짜·쿠폰 지문·목록가·상품번호가 모두 맞는 결과를 복원하는 방식으로 보완했다. 새로운 관측을 우선한다.
- 통신 실패와 실행 시간 초과는 미처리로 남겨 재검증한다. 쿠폰 미적용·삭제·품절처럼 서버가 확인해 준 미검증 사유는 통신 실패와 구분한다.

## 판단 및 남은 경미한 제약

- 명시된 수정·테스트·재수집·공개 권한과 기존 Native 선택을 유지해 중복 승인 없이 진행했다.
- 과거 날짜 가격을 오늘의 API 값으로 덮어쓰지 않는다. 당시 근거가 없는 가격은 비교에서 제외한다.
- artifact의 기존 관측이 현재 조건과 맞지 않더라도 더 최신 timestamp를 갖는 일부 경우, 오래된 유효 관측의 복원 대신 재조회가 늘어날 수 있다. 최종 worker/merge 검증이 불일치 가격의 공개를 막으므로 정확도 문제는 아니며 경미한 효율 개선으로 남겼다.

## 자동 재개

대기가 남으면 같은 날짜 안에서 최대 네 번 이어 실행하고, 완료되면 추가 실행을 만들지 않는다. 날짜 변경·잘못된 카운터·반복 상한·예약 실패는 명시적으로 실패한다. dispatcher 테스트 4개와 실제 최종 summary를 읽는 CLI의 `{"queued":false}` 종료를 확인했다. `GITHUB_TOKEN`의 workflow_dispatch 예외는 [GitHub 공식 문서](https://docs.github.com/en/actions/concepts/security/github_token)로 확인했다.

재개 예약 실패나 반복 상한 도달은 워크플로를 실패로 표시하므로 마지막 성공 배포가 유지된다. 그때는 이미 갱신된 partial Release DB의 추가 배포도 자동 중단된다. 이는 미완료를 조용히 성공으로 보고하지 않기 위한 운영 정책이다.
