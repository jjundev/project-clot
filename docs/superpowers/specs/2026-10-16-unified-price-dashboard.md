# 가격 추이 대시보드 출처 통합 설계

상태: 별도 워크트리에서 구현·테스트 및 독립 리뷰 수정 완료. 결과는 docs/verification/2026-10-16-unified-price-dashboard.md 참조. 작성일: 2026-10-16 KST.

## 목표와 확정 사항

사용자는 모든 수집 상품을 한 화면에서 검색하고, 출처와 브랜드를 선택해 결과를 좁힐 수 있다. 출처 버튼은 `전체 / 무신사 / 4910`이다. `전체`는 무신사와 4910의 합집합이며, 4910 찜과 일반 수집 상품을 별도 출처로 표시하지 않는다. 브랜드 선택창은 모든 출처에서 공통으로 제공한다.

브랜드는 다중 선택하고 즉시 반영한다. 미선택은 모든 브랜드를 뜻한다. 출처를 전환해도 이번 방문에서 선택한 브랜드는 유지한다. 선택한 브랜드가 새 출처에 없다면 0건과 해제 수단을 보여주고, 선택을 몰래 지우지 않는다. 새로고침 이후 브랜드 선택 저장은 추가하지 않는다.

기존 색상, 칩 디자인, 상품 카드와 차트의 시각적 체계는 유지한다. 고정 툴바의 전체 브랜드 나열을 검색 가능한 선택창으로 옮기고 선택 요약은 브랜드명 2개와 `외 N개`로 제한한다. 모바일에서는 선택창을 하단 시트로 표시한다.

## 조사 근거와 한계

- `src/dashboard.template.html:873-876`: 현재 전체 조회가 `4910all`을 제외한다.
- `src/dashboard.template.html:965-1010`: 빠른 필터, 카테고리, 출처의 집계에 검색어가 반영되지 않는다. 4910 수집 상품은 별도 빌드 총계만 사용한다.
- `src/dashboard.template.html:875`: 4910 브랜드 선택은 찜 상품에는 적용되지 않는다.
- `src/dashboard.template.html:166,555,825-827`: 공통 `display:flex`가 브랜드 영역의 `hidden` 표시와 충돌하는 구조다. 배포 브라우저에서 직접 재현한 것은 아니다.
- `src/visualizer.js:80-108,153-155`: ACTIVE 찜은 수집 파일에서 제외되어, 같은 4910 ID는 중복 집계하지 않는 구조다.
- 읽기 전용 로컬 DB와 현재 `derive()`를 사용한 점검: 무신사 전체 626, 최저가 489, 하락 119, 판매중 609, 품절 17. `나이키` 검색 결과는 4개지만 기존 빠른 필터 전체는 626을 계산한다.
- 첨부 화면의 4910 전체 139,503은 코드상 찜 9개를 포함한다. 같은 시점이라는 전제에서 전체는 `626 + 139,503 = 140,129`다. 이 값은 테스트 예시이며 운영 상수로 쓰지 않는다.
- 현재 로컬에 `data/4910.db`는 없다. 4910 운영 건수와 전체 규모의 성능은 아직 원본 DB로 확인하지 않았다. 미추적 `data/4910-all.js`는 입력 근거로 사용하거나 삭제하지 않는다.

## 데이터와 계산

선택한 방식은 전체 상품의 검색·카드용 요약을 읽고, 가격 이력은 필요할 때 읽는 방식이다. GitHub Pages와 로컬 `file://` 열기를 지원한다. 별도 서버 API는 도입하지 않는다.

상품 식별은 출처와 상품 ID의 조합이다. 다른 출처의 같은 숫자 ID는 별개다. 동일 4910 ID가 찜과 수집에 동시에 있으면 찜 데이터를 우선해 한 번만 포함한다. 회원가와 쿠폰가를 임의로 섞거나 더 낮은 가격으로 대체하지 않는다. 내부 수집 종류는 보존하되 출처로 노출하지 않는다.

브랜드 키는 표시명에 NFC, 앞뒤 공백 제거, 연속 공백 축약, 소문자 변환을 적용한다. 동일 키는 두 출처에서 공통 선택한다. 한글·영문 이름의 자동 번역이나 유사 이름 병합은 하지 않는다. 빈 이름은 기존 브랜드·판매자·출처 대체 표시를 유지한다.

기존 `derive()`의 가격 규칙을 공유 순수 함수로 옮긴다. 같은 가격 기준의 이력만 비교하고, 일반 수집 상품의 가격이 변하지 않았을 때 최저가로 표시하지 않는 기존 규칙도 유지한다. 가격 이력이 아직 다운로드되지 않았다는 이유로 관측 대기 상품으로 취급하지 않는다. `하락` 설명은 실제 계산에 맞게 `직전 관측 대비 하락`으로 표현한다.

각 필터의 숫자는 다른 조건을 유지한 채 해당 항목을 선택했을 때의 결과 수다.

| 집계 위치 | 적용 조건 | 제외 조건 |
|---|---|---|
| 출처 | 검색어, 브랜드, 카테고리, 빠른 필터 | 현재 출처 |
| 브랜드 | 검색어, 출처, 카테고리, 빠른 필터 | 현재 브랜드 선택 |
| 카테고리 | 검색어, 출처, 브랜드, 빠른 필터 | 현재 카테고리 |
| 빠른 필터·상단 KPI | 검색어, 출처, 브랜드, 카테고리 | 현재 빠른 필터 |
| 결과 건수 | 모든 조건 | 없음 |

동일 차원의 다중 브랜드 선택은 OR, 다른 차원 사이는 AND다. 항상 출처의 `전체 = 무신사 + 4910`, 빠른 필터의 `전체 = 판매중 + 품절`이 성립해야 한다. 최저가와 하락은 서로 겹칠 수 있다. 전체 결과와 실제 카드 렌더링 수를 분리해 `조건에 맞는 상품 N개 · 현재 M개 표시`로 안내한다. 카드 렌더링은 기존처럼 120개씩 한다. 모든 숫자는 천 단위 쉼표를 사용한다.

## 로딩과 오류

- 전체·4910 조회는 전체 요약을 확보하기 전 `집계 중` 상태다. 일부 파일만 읽은 결과를 전체 결과로 표시하지 않는다.
- 무신사만 선택하면 내장 요약으로 즉시 이용할 수 있다. 4910 로딩 성공은 무신사 화면이나 선택창을 임의로 바꾸지 않는다.
- 요약 요청 실패·내용 불일치에는 안내와 재시도를 제공한다. 로드 완료 후의 검색 0건과 실패를 구별한다.
- 원본 DB가 없거나 빌드에서 일부 4910 데이터가 제외된 경우 `4910 데이터 일부 미포함` 또는 `4910 데이터 미포함`을 표시한다. 0건으로 정상 수집 완료를 가장하지 않는다. 사용 가능한 무신사·찜 데이터는 유지한다.
- 상세 이력 실패는 해당 상세의 차트·기록 영역에만 영향을 준다. 요약 가격, 결과 건수, 필터, 정렬은 바뀌지 않는다.
- 파일별 빌드 revision을 검사해 다른 배포의 요약·이력이 섞이지 않게 한다. 느린 요청이 뒤늦게 완료되어도 현재 상세·출처 선택을 덮어쓰지 않는다.

## 호환성과 접근성

저장된 출처 `4910all`과 `4910`은 통합 `4910`으로 복원한다. 저장된 정렬 별칭 `coupon → priceAsc`, `couponRate → rate`를 유지한다. 기존 숫자 무신사 링크, `?goods=4910:ID&brand=SNO`, CLI의 타겟 상품 열기를 지원한다. 직접 상품을 열 때는 충돌하는 카테고리·브랜드·검색·빠른 필터를 해제해 결과 내 위치를 복원한다.

`hidden`이 공통 display 스타일보다 우선하도록 한다. 숨긴 요소는 화면 공간과 키보드 탐색에서 제외한다. 브랜드 선택창은 제목·검색 라벨·선택 상태를 제공하고 Escape로 닫히며 초점이 열기 버튼으로 돌아간다. 상품 상세와 브랜드 창을 동시에 열지 않는다. `/` 검색 단축키는 열린 브랜드 창을 침범하지 않는다. 고정 툴바 위치는 실제 상단 헤더 높이를 사용해 줄바꿈 시 겹치지 않게 한다.

## 완료 기준과 범위

중복·동일 숫자 ID·가격 기준 변경·관측 없음·검색·필터 교차·부분 실패·재시도·빠른 출처 전환·이전 링크·모바일·키보드 조작을 검증한다. 데이터 요약과 실제 상세 계산이 같아야 하고, 이력을 읽어도 결과와 정렬은 불변이다. 140,129개의 합성 요약으로 전체 검색과 120개 렌더링을 검증하고 실제 DB 접근이 가능하면 실제 규모 성능을 별도로 기록한다. 합성 검증을 운영 DB 검증으로 보고하지 않는다.

수집 대상·DB 스키마·회원가와 최저가 판정 기준·다른 쇼핑몰 상품의 동일 모델 병합은 이번 범위에서 바꾸지 않는다. 구현은 별도 워크트리에서 진행하고, 배포·main 통합·push는 이 계획 작성만으로 실행하지 않는다.
