# 무신사 디자인을 적용한 CLOT 가격 추적 화면

## 의도와 확정 범위

현재 CLOT 대시보드에 `rea-musinsa`의 검은 헤더, 이미지 중심 상품 목록, 타이포그래피를 적용한다. 사용자는 상품을 찾고 현재 가격이 수집 이력보다 저렴한지 판단할 수 있어야 한다. 기존 목록·검색·필터·상세·차트를 바꾸는 bounded 작업이다.

2026-10-25 채팅의 grill-yourself 설계를 문서화한다. 사용자가 후속으로 writing-plans를 요청했고 별도 선택을 바꾸지 않았으므로 결정 #7 **무신사·4910 모두 유지**, #8 **페이지형 상세**를 `[confirmed by default]`로 기록한다. 이번 요청은 설계·계획 문서 저장까지이며 구현·커밋·배포 승인은 아니다.

## 전역 제약

- Node.js 24, ESM, node:sqlite, node:test, 기존 Playwright를 사용하며 새 의존성을 추가하지 않는다.
- 무신사·4910 모두 유지하고 첫 방문 출처는 `all`, 가격 필터는 `all`, 정렬은 `dropAmt`로 한다.
- 기존 정상 저장값과 `4910all`, `coupon`, `couponRate` 호환을 유지한다. 전체 초기화는 새 기본값으로 돌아간다.
- 직접 확인·추정·미확인 가격, 확인일, 신규회원가, 적립금 적용 가정을 구분한다. 적립금 추정가로 현재 가격·정렬·차트·최저가·하락 판정을 대체하지 않는다.
- 신선도 48시간, 동일 기준 비교, 과거 기록 포함, 검증·보정된 4910 가격, 기존 최저가·하락 계산은 유지한다.
- 목록 배치는 120개, 목록 DOM의 상품 카드는 최대 360개, bootstrap 상품은 최대 120개를 유지한다. 목록에서는 상품별 가격 이력을 요청하지 않는다.
- 기본 상세 기간은 90일, 선택 기간은 7·14·30·90일·전체이며 전체는 `days:0`으로 조회한다.
- 최대 콘텐츠 폭 1440px, 상품 이미지 5:6, 검증 화면 폭 390·768·1440px, 모바일 상품 2열, 페이지 전체 가로 스크롤 없음.
- 저장된 테마는 복원하고 저장값이 없으면 밝은 본문을 기본으로 한다. 다크 모드도 유지한다.
- GitHub Pages `/project-clot/`와 로컬 `file://`에서 동작하고, 기존 `?goods=1`, `?goods=musinsa:1`, `?goods=4910:1`, 선택적 `brand`와 `targetGoodsNo`를 지원한다.
- 수집·DB 스키마·스냅샷 형식·공개 v2 데이터 계약·기존 메모리 제한을 변경하지 않는다.
- `rea-musinsa/`는 참고 자료로 보존하고 런타임 의존성으로 가져오지 않는다. 더미 상품·가격·후기·추가 사진·상거래 코드는 사용하지 않는다.
- 운영 DB, 생성된 `data/dashboard.html`, 다른 미추적 파일과 사용자 변경은 수정·삭제·스테이징하지 않는다.

## 화면과 동작

### 상품 목록

검은 헤더에 CLOT, 가격 추적 설명, 마지막 수집, 새로고침, 테마 전환을 둔다. 검색은 항상 보이는 목록 상단에 배치하고 브랜드·상품명·상품번호·지원 URL 검색, 한글 조합 입력을 유지한다.

큰 KPI 카드와 중복 가격 칩을 없애고 `전체 상품`, `가격 하락`, `수집 이력 최저가` 버튼에 개수를 붙인다. 버튼 그룹은 기존 `aria-pressed` 방식으로 조작한다. 판매중·품절은 보조 필터이며 검색·카테고리·브랜드·출처와 기존처럼 조합한다. 이 세 버튼은 복잡한 ARIA 탭 위젯으로 새로 구현하지 않는다.

출처 전체/무신사/4910, 카테고리, 복수 브랜드, 판매 상태, 과거 기록 포함, 정렬과 필터 해제를 유지한다. 첫 방문은 전체 상품을 하락폭 큰 순으로 보여주므로 하락 상품 0개라도 빈 홈이 되지 않는다. 결과 수는 집계 완료 후 확정하고 로딩·실패 중에는 `—`를 표시한다.

상품 카드는 이미지 → 브랜드·상품명 → 현재 혜택 적용 가격 → 비교 가능한 하락액·수집 이력 최저가 → 가격 출처·확인일 순서다. 정상가·할인율은 보조 정보다. 원래의 `역대 최저가` 문구는 `수집 이력 최저가`로 바꾸며 전 시장·전 기간의 최저가로 표현하지 않는다. 정상가 대비 할인과 직전 관측 대비 하락을 별개 정보로 표기한다.

적립금 병기는 기존 기능과 opt-in을 유지한다. 추정액을 카드에 보여주면 최소 보유 적립금·등급/카드 제외·확인 시점도 함께 표시하며, 상세에도 같은 조건을 제공한다. 쿠폰·추정 기준의 추가 설명은 상세에 둔다. 긴 수집 안내는 짧은 요약과 펼쳐보는 설명으로 정리하되 개별 상품의 추정 여부와 실패 상태는 접지 않는다.

### 페이지형 상품 상세

기존 팝업 대신 같은 HTML 안의 별도 상세 화면을 표시한다. 데스크톱에서 왼쪽은 대표 이미지·차트·가격 기록, 오른쪽은 브랜드·상품명·현재 가격·최저가/날짜·하락액·가격 기준·원본 링크다. 모바일은 요약 → 차트 → 기록 순서이고 대표 이미지 높이가 차트 접근을 과도하게 늦추지 않게 한다. 이미지가 없거나 실패해도 빈 이미지 영역과 텍스트·차트는 사용할 수 있다.

대표 이미지는 수집한 한 장만 쓴다. 차트는 기존 가격 계열과 직접/추정 표시를 유지하며 90일을 기본으로 한다. `무신사에서 보기 ↗` 또는 `4910에서 보기 ↗`를 제공한다. 가격 이력이 없으면 관측 대기, 조회 실패면 재시도, 차트 라이브러리 실패면 안내와 사용 가능한 기록 표를 보여준다.

목록에서 상세 진입은 history 한 항목을 추가한다. 이전/다음 상품 이동과 기간 변경은 항목을 추가하지 않는다. 브라우저 뒤로가기는 목록 조건·렌더링된 목록 구간·스크롤·포커스를 복원하고, 앞으로가기는 상세를 다시 연다. 상세 직접 진입·새로고침 후의 `목록으로`는 사이트 밖으로 나가지 않고 같은 경로의 목록을 표시한다. URL의 다른 query와 hash는 유지한다. 이 앱이 만든 현재 세션의 목록 진입점이 확인될 때만 `history.back()`을 사용한다.

페이지형 상세는 `role=dialog`, 모달 포커스 가두기, backdrop 닫기, body 스크롤 잠금을 사용하지 않는다. 상세 제목으로 포커스를 옮기고 목록 복귀 시 카드 또는 검색으로 돌린다. 브랜드 선택은 계속 네이티브 dialog다. 입력 중 좌우 화살표를 가로채지 않으며 이전/다음 버튼은 유지한다. Escape는 브랜드 dialog를 먼저 닫고 상세에서는 목록으로 돌아가는 단축키로 유지한다.

### 로딩과 복원

기존 요약·분할 인덱스·Worker·별도 이력 로딩을 유지한다. 상세를 보는 동안 목록 자동 더보기와 목록 윈도우 재배치를 중단한다. 늦게 도착한 목록·이력 응답은 현재 화면과 선택 상품을 덮어쓰지 않는다. 60초 신선도 갱신은 상세에서도 계속 적용하되 목록 복귀에 필요한 구간·앵커는 유지한다. 오래된 가격은 과거 기록 포함에서 접근 가능하며 하락·최저가 신호로 되살리지 않는다.

## 시각 기준

- 참고: `rea-musinsa/evidence/refinement-products.png`, `refinement-desktop.png`, `detail-desktop.png`와 해당 CSS·상품 카드.
- 검은 헤더 `#1a1b1f`, 본문 `#f4f4f4`, 잉크 `#111`, 구분선 `#e5e5e5`, 기존 Pretendard 스택을 사용한다. 신규 폰트 파일 복사는 하지 않는다.
- 카드 테두리·그림자·큰 반경을 줄인다. 상태는 색과 텍스트를 함께 사용하고 기존 의미 색의 대비를 유지한다.
- 1200px 이상 6열, 900–1199px 4열, 640–899px 3열, 639px 이하 2열. 상세는 900px 이상 2개 영역, 그 미만 1열이다.
- 가독성, 키보드 포커스, 터치 영역과 reduced-motion을 유지한다. 참고 구현의 최소 폭 744px와 과도한 헤더 높이는 복사하지 않는다.

## 제외

배너·기획전·이벤트·브랜드 홍보, 로그인·장바구니·결제·리뷰·문의·사이즈 추천, 신규 찜·알림, 목록별 미니 차트, 데이터 수집 변경, 프레임워크 전환, 원격 게시를 제외한다.

## 구현 경계와 검증

DOM·CSS·표시 및 조회 연결은 기존 `src/dashboard.template.html`에 둔다. history/URL 전이는 독립 테스트 가능한 `src/dashboard-navigation.js` factory로 분리하고 기존 모델·런타임 factory처럼 HTML에 직렬화한다. 분할 CSS·새 번들러·외부 runtime asset은 추가하지 않는다. `src/visualizer.js`와 대용량 fixture의 직렬화 경로를 모두 연결한다.

모델 기본 정렬, 탐색 상태 전이, 목록/상세 브라우저 흐름, 데이터 오류 복구, 적립금과 신선도, 440,129개 규모 목록과 120/360개 제한을 검증한다. 전체 기존 테스트와 Pages의 생성물 검증을 유지한다. 운영 DB 대신 임시 fixture로 실제 생성물을 만들고 검증한다. 같은 fixture·브라우저·화면 크기로 변경 전후 로딩을 비교하되 임의의 새 시간·RSS 합격선을 만들지 않는다. 데이터 삭제·힙 증설·검증 생략으로 회귀를 숨기지 않는다.
