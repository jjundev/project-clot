# 4910 가격 기준과 쿠폰 조건 교정

## 목적과 근거
사용자 요청: 가격 기준을 4910으로 통일하고 쿠폰 적용 조건을 반영하며, 테스트와 오수집 가격 재검증까지 수행한다.

2026-10-16 읽기 전용 실측:
- 상품 57821918은 기존 상세 요청에서 85,200원, AGLO 헤더를 추가하면 75,900원이다. 동일 옵션의 best-coupon은 5%, 할인액 3,790원을 반환한다. 기존 기록 81,410원은 서로 다른 플랫폼 기준을 섞은 계산이다.
- 상품 58451420은 각각 53,000원 / 47,100원, 할인액 2,350원이다.
- 10/14 Release의 회원 쿠폰함은 4장, 10/15는 15장이다. 후자에는 상품 2개 이상 25%, 3개 이상 30%, 국내 브랜드 2개 이상 22% 쿠폰이 포함된다.
- `conditions[1]`만 읽으면 수량 조건과 최소금액 위치가 바뀐 응답을 처리하지 못한다. `is_usable`은 현재 단품에 적용 가능하다는 뜻으로 사용할 수 없다.
- 판매처 61427 표본: 기준가 12,850원, API 할인 2,820원, 올림 후 10,030원. 현재 로컬 계산은 수량 조건을 무시해 9,000원이다.
- 해외 브랜드 5% 쿠폰 51416287은 377개 상품 한정이다. 해링턴·카고·하프집업·벨트가 목록에 포함된다.
- `best-coupon.is_applied`는 false/true가 모두 관측됐다. 의미를 공식 웹 호출 흐름과 비교하기 전에는 결제 적용 확정으로 해석하지 않는다.

## 요구사항
- Node.js 24, ES modules, node:sqlite, node:test를 유지한다. 새 외부 의존성을 추가하지 않는다.
- 상세·쿠폰·목록 가격은 AGLO 웹 식별 헤더로 일치시키고, 서로 다른 옵션이나 기준 시점의 가격을 섞지 않는다.
- 추적 가격은 수량 1, 쿠폰 1장, 포인트 차감 전 기준이다. 쿠폰 자동 발급·주문·계정 변경은 하지 않는다.
- 최소금액, 최소수량, 대상 상품/판매처/카테고리, 앱/유입 조건을 별도로 검증한다. 알 수 없거나 목록이 불완전하면 해당 쿠폰의 추정가를 확정 가격으로 쓰지 않는다.
- 판매처 표본에서 회원 쿠폰 하나가 적용됐다고 쿠폰함 전체나 판매처 전체에 적용 가능하다고 추론하지 않는다.
- 할인 계산은 서버 할인액이 있으면 그것을 우선하며 최종 가격을 10원 단위 올림한다. 기준가/옵션이 확인되지 않으면 기록하지 않는다.
- 회원 상세 응답과 best-coupon 및 공개 웹 흐름을 비교하여 `is_applied`와 옵션 가격 기준을 확인한다. 해석이 확인되지 않은 응답은 미검증으로 표시한다.
- API 실패·401/403·예산 초과·품절/옵션 없음은 가격 없음과 구분한다. 과거 쿠폰가를 신규 검증 가격으로 재사용하지 않는다.
- 과거 기록은 원본과 SHA256을 보존한다. 현재 가격을 과거 날짜의 정답으로 덮어쓰지 않는다.
- 당시 근거로 재계산할 수 있는 행만 교정하고, 나머지는 미검증/무효 상태로 가격 비교·최저가·하락 알림에서 제외한다. 제외 시 다른 잘못된 가격 필드로 폴백하지 않는다.
- 재검증은 로컬 DB 복사본과 알림 없는 보고서로 수행한다. 원격 Release/Pages 갱신은 검증된 결과와 실행 로그를 갖춘 뒤 별도 전달 단계로 취급한다.
- 무신사와 기존 관련 없는 변경(data/4910-all.js 및 unified-price-dashboard 문서 포함)은 건드리지 않는다.

## 완료 기준
결함을 재현하는 회귀 테스트, 전체 테스트 통과, 실제 찜 전건과 판매처 표본의 API 대조, 과거 영향 건수/교정 가능/미검증 분류 보고서, 재실행 멱등성 및 대시보드 오가격 제외 증거가 있다. 과거 시점 근거가 없는 가격은 복구 완료라고 보고하지 않는다.
