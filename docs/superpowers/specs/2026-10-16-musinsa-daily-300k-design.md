# 무신사 일상 조사 30만 확대

사용자가 승인한 목표: 쿠폰 목록 누락과 실행 시간 예산을 수정하여 매일 고유 상품 300,000개를 조사하고, 전체 실제 실행으로 확인한 최종 결과를 Markdown으로 저장한다. 앞선 두 검증 문서와 실측 원자료를 구현 근거로 사용한다. 추가 가정 검증 단계로 되돌리지 않는다.

## 구현 선택

- 기존 Node 24/SQLite/GitHub Actions를 유지한다. 기존 DB와 가격 이력을 보존한다.
- 기본 일상 경로는 공식 5대분류 아래 2단계 분류를 동적으로 발견하고, 서명 nextPageUrl을 순차적으로 따라 분류를 번갈아 읽는다. 전역 goods_no 중복 제거 후 정확히 300,000개에서 선택을 마친다. 조회 분류와 DB의 기존 top-level cat을 분리한다. 수집 병렬도 기본3, 요청 간격300ms.
- 대상은 전역 리뷰순 상위30만 또는 대분류 균등배분이 아니다. 모든 분류의 리뷰순 접두 구간을 번갈아 읽어 구성한 고유30만이다.
- 명시적 --category/--depth는 기존 부분 조사 경로를 유지한다. 목표 미달·분류 발견 실패·페이지 실패·deadline이면 불완전으로 보고하고 미노출 횟수를 올리지 않는다.
- 쿠폰 목록은 combined5대분류를 실제 hasNext=false까지 읽는다. API에서 엄격한 리뷰 내림차순이 확인되지 않았으므로 리뷰 floor로 중단하지 않는다. 60페이지 제한도 제거한다. 빈 페이지+hasNext 또는 비정상 페이지 반복/유한 안전상한은 실패로 보고하고 기존 매핑을 보존한다. 모든 USABLE 미만료 쿠폰을 조회한다. 회원 일일200+200회 제한은 유지한다.
- 수집45분, 번호 탐색12분(단계 시작부터), 판별15분(단계 시작부터), 전체 네트워크165분, Actions180분으로 정한다. 후처리15분을 남긴다. 단계 deadline은 전체 마감을 넘지 않는다. 기존 backfill 예산은 유지한다.
- 실제 배포 전 전체 테스트와 독립 리뷰. 이번 확대 요청은 검증된 구현의 병합·예약 작업 갱신·수동 전체 실행을 포함하는 것으로 해석하여 진행한다. Telegram은 기존 일상 실행의 기존 알림만 사용한다.
- 최종 문서에는 실제 Actions/DB의 선택 수, 완전성, 쿠폰 완료/실패/호출 수, 표본 정확도, 처리시간, 보존 증거를 기록한다. 실패를 성공이라고 쓰지 않고 원인을 수정해 다시 실행한다.
