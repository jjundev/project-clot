# 4910 전체 스캔 상품을 Pages 대시보드에 — 설계

Source: 2026-10-10 grill-yourself session. Needs-you rows #1, #9, #10 were answered "모두 추천대로" → **[confirmed]** at their assumed values.

## Intent
Pages 대시보드의 4910 영역은 지금 찜 상품만 보여 준다. 여기에 매일 스캔하는 유니클로·GU 판매글 전체(2026-10-10 기준 15,893건)를 추가한다. 이 데이터는 `index.html`에 인라인하지 않고 별도 파일 `4910-all.js`로 분리해, "4910 전체" 칩을 눌렀을 때만 불러오고 카드를 나눠 그린다. 완료 기준: Pages에서 "4910 전체"를 누르면 전체 판매글이 기존 카드 UI(검색, 카테고리, 최저가/하락/판매중 필터, 정렬, 상세 차트)로 보이고, 기존 첫 화면(무신사 + 찜)의 크기와 동작은 바뀌지 않는다.

Classification: architectural — 단일 HTML 데이터 계약을 깨고, 지연 로딩되는 두 번째 데이터 파일과 점진 렌더링을 도입한다.

## Behavior when done
- 출처 칩: `전체 · 무신사 · 4910 찜 · 4910 전체`. 기존 `data-src="4910"` 칩은 라벨만 `4910 찜`으로 바뀐다. `전체`는 지금처럼 무신사 + 4910 찜만 포함한다.
- `4910 전체`를 처음 누르면 그리드에 `4910 판매글 불러오는 중…`이 뜨고 `4910-all.js`를 받아 렌더링한다. 이후에는 다시 받지 않는다.
- 스캔 상품 카드: 셀러명, 표시가, 정가 대비 할인율, 역대 최저가 핀, 직전 스캔 대비 하락 핀. 기본 정렬은 기존 할인율순.
- 찜한 상품은 `4910 전체` 안에서 찜 데이터(내 회원가, 신규회원가)로 한 번만 나온다.
- 카드는 120장씩 그린다. 스크롤이 끝에 닿거나 `더 보기` 버튼을 누르면 120장을 더 그린다. 무신사 뷰에도 똑같이 적용된다.
- 상세 모달 차트는 가격이 바뀐 시점들을 잇는다. 버튼은 `4910에서 보기 ↗`.
- 실패 처리
  - 파일 로딩 실패: 그리드에 `4910 전체 목록을 불러오지 못했습니다`와 `다시 시도` 버튼. 다른 칩은 정상 동작.
  - `4910.db`가 없거나 깨짐: `4910 전체` 칩을 숨기고 무신사 대시보드는 그대로.
- 로컬 `visualize`(file://)에서도 동작한다. `<script>`를 삽입하는 방식이라 file://의 CORS 제한에 걸리지 않는다.

## Not in this round
- 스캔 상품의 회원가 — 1.6만 건마다 로그인 상세 조회가 필요하다.
- `DROPPED` 판매글 — 대시보드는 현재 판매 중인 것을 보는 용도. 이력은 DB에 남는다.
- 셀러 간 같은 제품 묶기 — 판매글(`sno`) 단위 추적이 원칙(README:43).
- 기본 `전체` 칩에 스캔 상품 포함 — #1.
- 모바일용 추가 경량화 — #10.

## Approaches
| Option | Approach | Pro | Con | Chosen |
|---|---|---|---|---|
| A | `index.html` + 별도 `4910-all.js` 지연 로딩, 기존 대시보드의 칩으로 통합 | UI 재사용, 첫 화면 크기 변화 없음 | 템플릿에 지연 로딩·점진 렌더링 추가 | ✔ |
| B | 별도 `4910.html` 페이지 | 기존 템플릿 무변경 | 카드·필터·모달·차트 복제 | — |
| C | 전부 `index.html`에 인라인 | 구조 변경 최소 | 첫 화면 4.3MB(gzip 1.1MB) | — |

## Implementation spec

### 1. `src/visualizer.js`
- `buildScan4910Payload(db4910)`
  - 읽는 범위: `goods WHERE status='ACTIVE'`(sno 오름차순)와 그 상품들의 `price_changes`(date, id 오름차순). 단 `liked_goods`(테이블이 있으면)의 ACTIVE sno는 제외한다.
  - 반환 형식:
    ```
    { v: 1, lastScan, imgBase: 'https://d3ha2047wt6x28.cloudfront.net/',
      b: [브랜드...], m: [셀러명...],
      r: [[sno, bIdx, mIdx, name, imgPath, firstSeen, cat, H], ...] }
    H = [[date, original_price, sale_price], ...]
    ```
  - `imgPath`: `image_url`이 `imgBase`로 시작하면 그 접두어를 뗀 값, 아니면 원래 값, 없으면 `''`.
  - URL은 저장하지 않는다. 클라이언트가 `https://4910.kr/goods/${sno}`로 복원한다(DB 실측 결과 15,893건 모두 이 규칙과 일치).
  - `cat` = `classifyCategory(name, brand)`.
  - `lastScan` = `scan_runs`의 가장 최근 `date`(불완전 스캔 포함). 없으면 `null`. 판매 중 판매글 중 가격 변동이 한 번도 없는 것은 `역대 최저가` 핀을 달지 않는다.
- `generateDashboardHtml`
  - `outputPath`와 같은 디렉터리에 `4910-all.js`를 쓴다. 내용은 `window.__CLOT_4910_ALL__ = <json>;\n`이고, `</script`는 기존처럼 이스케이프한다.
  - 메인 payload에 `has4910All`(boolean)과 `total4910All`(r.length)을 넣는다.
  - 4910 처리는 기존 `try/catch` 격리 원칙을 따른다(`src/visualizer.js:240-251`). 실패하거나 DB가 없으면 `has4910All:false`, `total4910All:0`으로 두고, 직전 빌드가 남긴 `4910-all.js`는 지운다.
  - 반환값에 `total4910All`을 추가한다.

### 2. `src/dashboard.template.html`
- `is4910(it)` = `it.src === '4910' || it.src === '4910all'`. 기존 `it.src === '4910'` 비교 6곳(`:697, :810, :819, :1042, :1045, :1144`)을 이 함수로 바꾼다.
- 출처 칩
  - `data-src="4910"`의 라벨을 `4910 찜`으로 바꾼다.
  - `data-src="4910all"` 칩(라벨 `4910 전체`, 카운트 `id="s4910all"`)을 추가한다. `D.has4910All`이 false면 숨긴다.
  - `SRC_KEYS`에 `4910all`을 추가한다.
- `inSrc(it)` 하나로 출처 판정을 통일하고, `matches`와 카운트 계산이 이 함수를 같이 쓴다.
  - `all`: `it.src !== '4910all'`
  - `4910all`: `is4910(it)`
  - 나머지: `it.src === state.src`
- 지연 로딩: `ensure4910All()` → Promise
  - 상태는 `idle | loading | ready | error`.
  - `<script src="4910-all.js?v=<encodeURIComponent(D.generatedAt)>">`를 삽입한다. `onload` 때 `window.__CLOT_4910_ALL__`를 펼쳐 `D.items`에 넣고 파생 지표를 계산한다. `onerror` 때는 error 상태로 바꾸고 script 태그를 제거해서 재시도할 수 있게 한다.
- 펼친 아이템의 필드
  - `n: sno`, `k: '4910:'+sno`, `src: '4910all'`, `b: b[bIdx]`, `m: m[mIdx]`, `g: name`
  - `u: 'https://4910.kr/goods/'+sno`, `i: imgPath ? imgBase+imgPath : ''`
  - `s: 'ACTIVE'`, `c: cat`, `fs: firstSeen`
  - `L`: H의 각 행을 `[date, original, sale, sale, 0, '표시가', 0]`으로 바꾼다. `lastScan`이 있고 마지막 행의 date가 그보다 이르면, 마지막 가격으로 `lastScan` 행을 하나 덧붙인다.
- 파생 지표 계산(`:670-707`)은 `derive(it, idx)` 함수로 빼서 나중에 들어온 아이템에도 적용한다. `COUNTS`는 `render()`가 매번 다시 계산한다.
- 그리드 상태 메시지와 재시도
  - loading: `4910 판매글 불러오는 중…`
  - error: `4910 전체 목록을 불러오지 못했습니다`와 `<button data-retry-4910>다시 시도</button>`
- 카운트: `s4910all`은 로드 전에 `D.total4910All`, 로드 후에는 실제 개수(찜 포함)를 표시한다.
- 시작 시 `state.src === '4910all'`(localStorage에서 복원)이면 즉시 `ensure4910All()`을 호출한다.
- 점진 렌더링
  - `PAGE = 120`. `render()`는 `view`를 계산한 뒤 첫 120장만 그린다.
  - 남은 카드가 있으면 그리드 뒤에 `<button id="gridMore">더 보기 (남은 N개)</button>`을 둔다. 이 버튼을 `IntersectionObserver`(rootMargin `600px`)로 관찰해 보이면 `renderMore()`를 자동 호출한다. 클릭해도 같은 동작이다.
- `openModal`(`:972`)이 view 밖의 아이템을 열 때 `state.src = 'all'`로 리셋하는데, `4910all` 아이템이면 `'4910all'`로 리셋해야 한다.
