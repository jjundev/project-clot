# ask-musinsa 프로젝트 로컬 스킬 설계

## 확정한 사용자 요구

- 무신사를 조사하는 `ask-musinsa` 스킬을 이 프로젝트에 로컬로 둔다.
- 기존 `opencli musinsa`의 조회 명령 10개를 모두 스킬에서 사용할 수 있게 한다.
- 구조화된 상품 정보만으로 답이 부족할 때 상세 페이지의 PNG 등 이미지에 있는 내용을 읽는다.
- 후기 내용이 질문에 중요하면 후기 본문을 읽는다. 후기 사진은 필요한 경우에만 판독한다.
- 이번 범위는 스킬 작성이며 기존 OpenCLI 어댑터 수정은 포함하지 않는다.

## 현재 확인한 경계

`opencli musinsa --help -f yaml`의 명령은 `likes`, `login`, `my-prices`, `mysize`, `options`, `orders`, `product`, `recommend`, `search`, `whoami`다. 세부 옵션은 실행 시 도움말로 확인한다. `product`는 HTML의 `__NEXT_DATA__`에서 구조화된 필드를 읽고 후기 점수·개수를 반환한다. 상세 이미지의 픽셀과 후기 본문은 읽지 않는다. 근거: `/Users/hyunjun_macbook_pro/.opencli/clis/musinsa/product.js` 19~94행. OpenCLI 브라우저에는 `extract`, `state`, `screenshot`, `scroll`, `click`이 있다.

## 사용자에게 보일 동작

1. 검색어·상품 URL·상품번호·계정 관련 질문을 구분한다. 상품을 확정하기 전 다른 상품이나 옵션의 정보를 섞지 않는다.
2. 명령의 JSON 출력을 먼저 확인하고, 질문에 필요한 명령만 순차적으로 실행한다. 계정 명령은 사용자의 계정 정보가 필요한 질문에서만 사용한다.
3. 상세 이미지에만 답이 있거나 텍스트와 이미지가 충돌하면 브라우저에서 이미지가 실제로 표시된 상태를 캡처하여 시각 판독한다. 판독할 수 없는 작은 글씨는 추측하지 않는다.
4. 후기·착용감·구매 판단을 물으면 점수와 개수만으로 후기 내용을 요약하지 않는다. 상품 페이지의 후기 본문을 읽고, 질문에 따라 후기 사진도 살핀다. 읽은 표본 수와 선택 기준을 밝힌다.
5. 답변은 명령의 구조화 필드, 상세 이미지, 후기 본문·사진 중 출처를 구분한다. 가격·재고에는 조회 시점을 표시하고, 접근 실패·미확인 영역을 명시한다.

## 구현 위치와 분리

이 저장소의 로컬 스킬 원본은 `.agents/skills/`에 둔다. 원본은 `.agents/skills/ask-musinsa/SKILL.md`, 상세 절차는 `.agents/skills/ask-musinsa/references/detail-and-reviews.md`, Claude 발견 경로는 `.claude/skills/ask-musinsa -> ../../.agents/skills/ask-musinsa`다. 계정 정보·상품별 사례 데이터는 스킬에 저장하지 않는다.

## 범위 밖

- OpenCLI 어댑터의 새 명령·파서·API 구현.
- 구매, 장바구니, 좋아요 변경, 리뷰 작성.
- 무신사 외 사이트나 커뮤니티의 여론을 무신사 후기와 합산하는 기능.

## 수용 기준

- 스킬 형식 검증에 통과하고 프로젝트의 `.agents/skills/ask-musinsa/SKILL.md`로 접근할 수 있다.
- 10개 명령의 용도와 명령 선택 기준이 누락 없이 기술된다.
- 일반 상품 정보, 이미지 상세, 후기 질문을 서로 다른 경로로 처리한다.
- 이미지·후기 미접근 또는 로그인 필요 상태에서 확인하지 않은 내용을 사실처럼 말하지 않는다.
- 실제 상품을 이용한 읽기 전용 검증에서 추출 근거와 접근 한계를 기록한다. 사이트가 차단되면 성공으로 간주하지 않고 제한을 남긴다.
