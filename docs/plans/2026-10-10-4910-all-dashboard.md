# 4910 All Listings on the Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Pages dashboard gets a `4910 전체` source chip. The chip lazy-loads every ACTIVE scanned Uniqlo/GU listing from a separate `4910-all.js`, and the grid renders cards 120 at a time.

**Architecture:** `src/visualizer.js` gains `buildScan4910Payload(db4910)`, and `generateDashboardHtml` writes its output as `window.__CLOT_4910_ALL__` to `4910-all.js` next to `index.html`. `src/dashboard.template.html` injects that script on demand, expands the compact rows into dashboard items (`src: '4910all'`), and replaces the one-shot `grid.innerHTML` with paged rendering.

**Tech Stack:** Node.js 24 ESM, `node:sqlite` `DatabaseSync`, `node:test` + `node:assert/strict`, vanilla ES5 in the template, Chart.js 4.4.4 (already loaded), GitHub Pages.

**Spec:** `docs/specs/2026-10-10-4910-all-dashboard.md`

## Global Constraints

- Data file name `4910-all.js`, written next to the dashboard HTML. Content `window.__CLOT_4910_ALL__ = <json>;\n`, with `</script` escaped the way `src/visualizer.js:266` does.
- Payload shape `{ v: 1, lastScan, imgBase: 'https://d3ha2047wt6x28.cloudfront.net/', b: [...], m: [...], r: [[sno, bIdx, mIdx, name, imgPath, firstSeen, cat, H]] }`, `H = [[date, original_price, sale_price], ...]`.
- Item URL `https://4910.kr/goods/${sno}`; item key `'4910:' + sno`; item `src` `'4910all'`.
- Expanded tuple `[date, original, sale, sale, 0, '표시가', 0]`.
- Main payload adds `has4910All` (boolean) and `total4910All` (number).
- Exact copy: chip labels `4910 찜` / `4910 전체`, `4910 판매글 불러오는 중…`, `4910 전체 목록을 불러오지 못했습니다`, `다시 시도`, `더 보기 (남은 N개)`.
- `PAGE = 120`; IntersectionObserver `rootMargin: '600px'`.
- The `전체` chip still means Musinsa + 4910 liked only; default sort unchanged (`rate`).
- A 4910 failure never blocks the Musinsa dashboard or the Pages deploy.
- Never run `daily` or a non-`--dry-run` `track-4910` locally (Actions owns `data/4910.db` and pushes). Manual builds go to a scratch directory via `CLOT_DASHBOARD_PATH`.
- Work on branch `feat/4910-all-dashboard`, not `main`.

## Review Focus

1. A listing whose last price change was weeks ago must show no 하락 pin; only a change on the latest complete scan date counts. → Task 4 browser check A.
2. A rebuild after 4910 starts failing must not leave yesterday's `4910-all.js` behind with the chip showing stale data. → Task 2 `a failing 4910 build removes a stale 4910-all.js`.
3. A liked listing must appear once in `4910 전체`, with its member price, never twice. → Task 1 `liked ACTIVE listings are excluded`, Task 4 browser check B.
4. Opening a `4910all` card's modal and then stepping prev/next past the rendered 120 must keep working, and a deep-link reset must not drop the user into `전체` where the item is absent. → Task 3 (`openModal` reset), Task 4 browser check C.
5. A user whose saved `src` is `4910all` reloads the page: the data must load on boot rather than showing an empty grid. → Task 3 step, Task 4 browser check D.
