# 4910 상위 100 브랜드 × 우수 셀러 추적 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 4910 랭킹 상위 100 브랜드(+유니클로·GU)를 매일 스캔하고, 구매만족도 95%·리뷰 100 이상 셀러의 판매글만 목록가와 내 쿠폰가로 기록한다. DB는 GitHub Release에 두고 별도 workflow에서 돌린다.

**Architecture:**
- 기존 `src/site4910/` 모듈(client → scan → store → digest)을 넓힌다.
- 새 모듈 4개:
  - `brands.js`: 브랜드 목록
  - `sellers.js`: 셀러 판정
  - `coupons.js`: 쿠폰가
  - `release.js`: DB 내려받기·올리기
- `track.js`가 이들을 엮어 브랜드 단위로 병렬 스캔하고 저장한다.
- 대시보드는 브랜드별 JS 파일로 나눠 지연 로딩한다.

**Tech Stack:**

**Spec:** `docs/specs/2026-10-11-4910-top100-sellers.md`. 조사 근거는 `docs/verify/4910-member-price.md`이다.

## Global Constraints
- 비로그인 요청 헤더: `X-Anonymous-Token`, `Origin: https://4910.kr`, `Referer: https://4910.kr/`. 기존 `getJson`을 그대로 쓴다.
- 4910 회원 요청(쿠폰함, best-coupon) 헤더: `X-App-Type: AGLO`, `X-App-Version: 0.1.0`, `X-Device-Type: PCWeb`, `Authorization: JWT <token>`.
- `/aglo/api/goods/*`는 호출하지 않는다(Cloudflare 403, 우회 금지).
- 셀러 통과 기준: `satisfaction >= 95 && (reviews_count ?? 0) >= 100`
- 고정 브랜드: 유니클로 `2421`, GU `13647`. 랭킹 상위 `100`개 + 고정.
- 브랜드 목록 갱신: 월요일(UTC 기준 `getUTCDay() === 1`) 또는 `brands` 테이블이 비었을 때.
- 셀러 재조회 주기: `7`일. 하루 셀러 조회 상한: `300`.
- 스캔 동시 실행 수: 기본 `3`, 범위 `1-4`. 작업자마다 클라이언트를 따로 만든다(요청 간격 300ms는 작업자 단위).
- 스캔 예산: `BUDGET_MS_4910 = 25 * 60_000`
- 쿠폰가: `ceil10(L − max(min(max, floor(L·%/100))))`. 정액 쿠폰은 `min(max, price)`. `L < min`인 쿠폰은 제외.
- 쿠폰가 변화는 `price_changes`에 기록하지 않는다.
- Release 태그 `data-4910`(prerelease). 첨부 파일 `4910.db.gz`(최신)와 `4910.db.prev.gz`(직전).
- **Release DB를 내려받지 못하면 스캔하지 않는다.**
- 토큰 값은 로그·에러 메시지·텔레그램 어디에도 찍지 않는다(기존 규칙).
- 텔레그램 메시지 한 통은 4096자 이하(기존 규칙).

## Deviations from spec
- spec §6의 `scripts/4910-db.js` 대신 CLI 명령 `node src/cli.js 4910-db pull|push`(`src/site4910/release.js`)로 만든다. workflow와 로컬이 같은 진입점을 쓰기 위해서다.
- spec §6의 "첨부 파일이 없으면 git의 `data/4910.db`로 시작" 대신 **최초 1회 수동 `push`**(Task 11)로 시작한다. `pull`은 첨부 파일이 없으면 항상 실패한다. 이 편이 "빈 DB로 시작 금지" 원칙과 맞는다.
- spec §4의 `coupon_daily` 테이블은 만들지 않는다. `market_coupons`가 `(market_sno, date)` 키로 같은 정보를 갖는다.

## Review Focus
1. **Release에 첨부 파일이 없거나 다운로드가 중간에 끊긴 경우** → 스캔을 시작하지 않고 실패해야 한다. 빈 DB로 덮어쓰면 이력을 잃는다. (Task 9 테스트)
2. **기준 미달이 된 셀러, 랭킹에서 빠진 브랜드의 판매글** → `OUT_OF_SCOPE`가 되어야 하고, DROPPED·miss·`price_changes` 이벤트가 생기면 안 된다. 다시 들어오면 `REVIVED`. (Task 2 테스트)
3. **불완전 스캔된 브랜드** → 그 브랜드 판매글만 miss를 세지 않는다. 다른 브랜드에는 영향이 없어야 한다(브랜드 단위 applyScan). (Task 2 테스트)
4. **회원 토큰이 없거나 만료된 날** → 목록 스캔과 저장은 정상 진행하고, `coupon_price`는 NULL, 요약에 만료 경고. (Task 5·8 테스트)
5. **판매처 표본의 실제 할인과 계산이 다를 때**(쿠폰 정책 변경) → `coupon_mismatch` 경고. 그 판매처 쿠폰가는 NULL로 둔다(틀린 값을 공개하지 않는다). (Task 5 테스트)

### Task 5: 쿠폰가 — `coupons.js`

**Files:**
- Create: `src/site4910/coupons.js`
- Test: `tests/site4910-coupons.test.js`

**Interfaces:**
- Consumes: `client.getMyCoupons`, `client.getGoodsDetail`(비로그인, `optionSno`), `client.getBestCoupon`, store의 `replaceWallet`/`getWallet`/`addMarketCoupon`/`recordMarketCoupon`/`getMarketCoupons`/`getQualifiedSamples`/`setCouponPrices`
- Produces
  - `export function couponDiscount(L, c) → number`: `L < c.min`이면 0. PERCENT면 `Math.min(c.max ?? Infinity, Math.floor(L * c.percent / 100))`, PRICE면 `Math.min(c.max ?? Infinity, c.price)`.
  - `export function couponPrice(L, coupons) → number`: `Math.ceil((L − max(0, ...discounts)) / 10) * 10`. 결과가 L보다 크면 L로 둔다.
