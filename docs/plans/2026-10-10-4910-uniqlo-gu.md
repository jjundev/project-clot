# 4910 Uniqlo·GU Price Tracking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every daily run also scans all ~15.9k Uniqlo and GU listings on 4910.kr, records price changes / new / ended listings in a separate `data/4910.db`, and sends one Telegram digest, without ever blocking the Musinsa run.

**Architecture:** A self-contained `src/site4910/` module: `client.js` (anonymous token, list API, price-range bisection scan), `store.js` (SQLite with change-only history), `digest.js` (Telegram HTML), `track.js` (orchestration + runner probe). `src/cli.js` gets an exported `run4910Step` that `handleDailyRun` calls inside a try/catch before the git export, plus a `track-4910` command.

**Tech Stack:** Node.js 24 ESM, global `fetch`, `node:sqlite` `DatabaseSync`, `node:test` + `node:assert/strict`.

**Spec:** `docs/specs/2026-10-10-4910-uniqlo-gu.md`

## Global Constraints

- Brands: `{ sno: 2421, key: 'uniqlo', name: '유니클로' }`, `{ sno: 13647, key: 'gu', name: 'GU' }`; query always uses `member_gender=ALL&sorting_type=NEW`.
- Token URL `https://api.a-bly.com/api/v2/anonymous/token/`; list URL `https://api.a-bly.com/aglo/api/brands/{sno}/goods/?brand={sno}&member_gender=ALL&sorting_type=NEW&limit=500` plus optional `&min_price=`, `&max_price=`, `&last_sno=` (append only when non-null).
- Request headers: `User-Agent` = `USER_AGENT` from `src/myprice.js`, `X-Anonymous-Token`, `Origin: https://4910.kr`, `Referer: https://4910.kr/`, `Accept: application/json`.
- Page limit 500; slice cap 2,500; completeness tolerance 1% of brand total; 300 ms between requests; 15 s timeout per request.
- Listing URL: `https://4910.kr/goods/{sno}`.
- DB path: `process.env.CLOT_4910_DB_PATH || <repo>/data/4910.db`, read at construction time (not module load).
- History is change-only: rows in `price_changes` only for `NEW`, `PRICE`, `DROPPED`, `REVIVED`.
- DROPPED after 2 consecutive complete-scan misses; misses count at most once per date.
- Drop alert: `(prev - cur) / prev >= 0.10`, top 10 by drop rate; Telegram message ≤ 4096 chars.
- A 4910 failure never throws out of the daily run and never prevents the Musinsa git commit.
- Every new test file's first line is `import './setup-env.js';` (enforced by `tests/test-isolation.test.js`).
- Not in this round: dashboard/Pages, cross-seller product grouping, member prices, 4910 rows in `latest_prices.json`.

## Review Focus

1. `daily --force` the same day twice → a listing missing both times gets `misses` 1, not 2, and nothing is double-logged. Test: Task 3 `same-day rerun is idempotent`.
2. One brand's scan dies halfway (network / 5xx after retries) → that brand's unseen listings keep `misses` unchanged; the other brand still counts misses. Test: Task 3 `incomplete brand freezes misses`, Task 4 `brand failure marks it incomplete`.
3. A listing whose price moves between two slice queries shows up in both slices (or neither) → counted once; a single run never drops it. Test: Task 2 `dedupes a sno seen in two slices`.
4. Seller names / titles containing `<`, `>`, `&` (e.g. `[~10/15 한정특가]`, `M&M`) → Telegram `parse_mode=HTML` must not reject the message. Test: Task 4 `escapes HTML in names`.
5. Cloudflare/4910 blocks the GitHub runner (token request 403) → daily logs one warning, Musinsa data still commits, process exit code stays 0. Test: Task 5 `run4910Step swallows a client failure`.

Algorithm (the tests don't fully determine it):

```text
brandTotal = listBrandGoods({brandSno, limit: 1}).totalCount      // throw → complete=false, problems=['brand total: …'], return
stack = [[0, null]]                                                 // [lo, hi], hi null = open
while stack:
  [lo, hi] = pop
  total = listBrandGoods({brandSno, minPrice: lo, maxPrice: hi, limit: 1}).totalCount
  if total > sliceMax and (hi === null or hi > lo):
     mid = hi === null ? max(lo * 2, 100000) : floor((lo + hi) / 2)
     push [lo, mid - (hi === null ? 1 : 0)] and [mid + (hi === null ? 0 : 1), hi]; continue
  if total > sliceMax: problems.push(`unsplittable ${lo}-${hi}`)
  sliceTotalSum += total
  page with lastSno until lastSno null or entries empty, at most ceil(sliceMax / PAGE_LIMIT) + 5 pages (hitting the cap → problem)
  any throw inside a slice → problems.push(`slice ${lo}-${hi}: ${err.message}`), continue to next slice
complete = problems.length === 0 && |sliceTotalSum - brandTotal| <= brandTotal * COMPLETE_TOLERANCE
```
