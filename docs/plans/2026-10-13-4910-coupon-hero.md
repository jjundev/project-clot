# 4910 전체 쿠폰가 히어로 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 4910 전체 판매글의 날마다 실구매가를 쿠폰가로 정한다. 큰 가격, 할인율, 정렬, 최저가·하락 핀, 차트, 표가 모두 이 값을 따르게 한다.

**Architecture:**
- 쿠폰가가 바뀐 날만 `coupon_price_changes`에 쌓는다. 회원 쿠폰 학습이 `ok`인 실행에서만 쌓는다.
- `buildScan4910Payload`가 표시가 이력과 쿠폰가 이력을 날짜별 `[date, original, sale, cp]`로 합친다. 합치는 규칙: 표시가가 같고 마지막 정상 실행에서 3일 안일 때만 이전 쿠폰가를 이어 쓴다.
- 템플릿은 `cp`로 각 행의 실구매가와 기준(`'쿠폰가'`/`'표시가'`)을 정한다. 기존 `derive`/`fillTable`의 같은 기준 규칙이 나머지를 처리한다.

**Tech Stack:** Node 24 ESM, `node:sqlite`, `node:test`, 단일 HTML 템플릿(바닐라 JS, Chart.js)

**Spec:** `docs/specs/2026-10-13-4910-coupon-hero.md`. 배경은 `docs/specs/2026-10-11-4910-top100-sellers.md`와 `docs/specs/2026-10-11-4910-coupon-parallel.md`이다.

## Review Focus
1. 같은 날 `ok` 실행 뒤에 `expired` 실행: `scan_runs.coupons_ok`가 0으로 덮여도 그날 쿠폰가가 유지되어야 한다. 쿠폰 이력 행이 있는 날짜도 정상 날짜로 친다. → Task 3 `a coupon row's own date counts as a priced day`
2. 같은 날 다시 실행해 쿠폰가가 원래대로 돌아옴: 그날 행이 지워져야 한다. 남아 있으면 가짜 변동이 생긴다. → Task 1 `a same-day rerun replaces today's row and removes it when the pair returns`
3. 토큰 만료일에 표시가가 바뀐 판매글: 그날은 표시가 기준이고, 다음 `ok` 날에 새 쿠폰가로 돌아와야 한다. → Task 3 `a sale change after the last coupon row is unknown`
4. 쿠폰가가 있던 판매글의 셀러가 숨김이 됨(null 행): 그날부터 표시가 기준이고, 숨김이 풀리면 쿠폰가로 돌아와야 한다. → Task 3 `a null coupon row switches to 표시가 and back`
5. 예전에 `coupon` 정렬을 저장해 둔 사람: 정렬 select가 비지 않고 "실구매가 낮은 순"으로 열려야 한다. → Task 4 Step 6 브라우저 확인
